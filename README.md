## Сюжет

История должна содержать не менее 10 сцен (узлов) и не менее 5 различных концовок.

Каждая сцена имеет несколько вариантов выбора, которые приводят к разным узлам сюжета.

Сюжет должен быть связанным (из точки старта можно попасть в любую концовку).

Концовка определяется алгоритмически — например, по набору параметров (здоровье, удача, карма, опыт).

## Структура программы

Логика игры реализуется с помощью классов и функций.

Основная часть — класс GameEngine, который управляет:

загрузкой сюжета;

обработкой выбора пользователя;

сохранением состояния;

выводом текста.

Каждая сцена — отдельный объект или словарь, содержащий текст и список вариантов выбора.

## Использование структур данных

Программа должна использовать:

словарь (dict) для хранения сцены;

множество (set) для хранения посещённых узлов;

список (list) для истории выборов.

## Алгоритмические элементы

Не менее двух алгоритмических приёмов, например:

поиск пути к концовке (BFS/DFS) (Например: Когда игрок достигает концовки, можно посчитать, через какие сцены можно было добраться до этой концовки.);

рекурсивный обход дерева решений (Например: Можно посчитать все возможные концовки, используя рекурсию, которая обходит сюжет как дерево.);

подсчёт очков (Например: Во время игры параметры (health, karma, experience) изменяются. Можно добавить алгоритм подсчёта итогового “рейтинга героя”.);

динамическое вычисление состояния игрока (Например: Параметры персонажа (например, здоровье, удача, карма) меняются в зависимости от предыдущих действий — это можно оформить как динамическое вычисление).

## Работа с файлами

При завершении игры программа должна записывать в текстовый файл (results.txt):

имя игрока;

сделанные выборы;

финальное состояние (например, здоровье, опыт, очки);

название концовки.
